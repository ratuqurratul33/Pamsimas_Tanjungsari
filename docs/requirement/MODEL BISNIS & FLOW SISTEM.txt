# MODEL BISNIS & FLOW SISTEM PAMSIMAS — FINAL

Dokumen ini merupakan rancangan terbaru sistem **Digitalisasi PAMSIMAS** berdasarkan seluruh hasil observasi, wawancara, dan revisi alur bisnis.

Sistem terdiri dari **3 sisi utama**:

1. **Publik** — melihat informasi dan transparansi PAMSIMAS.
2. **Petugas Penagih** — melakukan pekerjaan lapangan.
3. **Admin** — mengelola seluruh proses PAMSIMAS.

> **Catatan:** Tidak ada lagi pembagian hak akses Admin Ketua, Bendahara, atau Perangkat Desa. **Satu role Admin memiliki seluruh fitur pengelolaan sistem.**

# 9. FLOW INPUT METER

Pada periode pencatatan, petugas mendatangi rumah pelanggan.

Misalnya:

> **Tanggal 10**

Petugas:

1. Mencari pelanggan.
2. Membuka data pelanggan.
3. Melihat meter sebelumnya.
4. Memasukkan meter saat ini.
5. Sistem menghitung pemakaian.

Formula:

```text
Meter Saat Ini - Meter Sebelumnya
= Pemakaian Air
```

Contoh:

```text
Meter sebelumnya = 100 m³
Meter sekarang   = 112 m³

Pemakaian = 12 m³
```

Sistem kemudian menghitung tagihan berdasarkan tarif yang telah ditentukan Admin.

# 10. FLOW CETAK KWITANSI

Fitur ini penting karena proses PAMSIMAS **tetap menggunakan kwitansi fisik yang sudah digunakan sebelumnya**.

Sistem bukan mengganti kwitansi lama, tetapi membantu Admin mencetaknya secara lebih cepat.

## Alur

```text
Petugas mencatat meter
        ↓
Data pemakaian masuk sistem
        ↓
Tagihan terbentuk
        ↓
Admin membuka Cetak Kwitansi
        ↓
Pilih periode
        ↓
Pilih wilayah / petugas
        ↓
Sistem menampilkan daftar tagihan
        ↓
Admin memilih tagihan
        ↓
Cetak Kwitansi
        ↓
Kwitansi diberikan kepada Petugas
```

## Cetak Kwitansi Massal

Admin dapat memilih:

* Bulan/periode
* Dusun
* RT
* Petugas
* Status tagihan

Kemudian sistem menghasilkan kumpulan kwitansi.

### Isi kwitansi

* Nomor tagihan
* ID pelanggan
* Nama pelanggan
* Alamat/RT
* Pemakaian air
* biaya admin 5.000
* Nominal tagihan
* Informasi pembayaran
* Elemen desain kwitansi resmi

Sistem menggunakan **template kwitansi yang sudah dimiliki PAMSIMAS**.

Data digital ditempatkan pada posisi yang sesuai dengan template tersebut.

# 13. VERIFIKASI TRANSAKSI

# 15. AKSI VERIFIKASI

Admin dapat melakukan verifikasi per transaksi.

Namun untuk mempermudah pekerjaan, tersedia:

> **Lunaskan Semua**

Jika seluruh bukti dan uang telah sesuai.

Flow:

```text
Admin membuka setoran
        ↓
Memeriksa total
        ↓
Memeriksa bukti
        ↓
Memeriksa daftar pelanggan
        ↓
        ┌───────────────┐
        │               │
   Sesuai            Tidak Sesuai
        │               │
        ↓               ↓
Lunaskan Semua       Tolak
        │
        ↓
Status pelanggan → Lunas
        ↓
Setoran → Terverifikasi
        ↓
Dana masuk ke Kas
```

Jika tidak sesuai, Admin dapat menolak transaksi tertentu dan memberikan alasan.

# 16. HUBUNGAN VERIFIKASI DENGAN KAS

Setelah Admin menyetujui transaksi:

### Tunai

```text
Pembayaran Tunai
      ↓

      ↓
Kas Tunai + Rp...
```

### QRIS

```text
Pembayaran QRIS
      ↓
Verifikasi
      ↓
Kas QRIS + Rp...
```

Jadi transaksi **baru menjadi pemasukan kas resmi setelah diverifikasi**.

# 33. PEMAHAMAN INTI SISTEM

Pada akhirnya, sistem ini memiliki **tiga alur besar**:

### A. Alur Operasional

> **Pelanggan → Petugas → Tagihan → Pembayaran → Verifikasi**

### B. Alur Keuangan

> **Verifikasi → Kas Tunai/Kas QRIS → Pengeluaran/Mutasi → Laporan**

### C. Alur Monitoring

> **Data Pembayaran → Transparansi Wilayah → Dusun → RT → Pelanggan → Tindak Lanjut Penagihan**

Ketiganya saling terhubung, tetapi fungsi masing-masing tetap jelas.

**Admin mengelola seluruh siklus. Petugas menjalankan proses lapangan. Publik hanya menerima informasi yang memang layak dipublikasikan.**

Dengan model ini, digitalisasi tidak memaksa PAMSIMAS meninggalkan proses lama yang masih dibutuhkan—seperti **kwitansi fisik dan pembayaran langsung kepada petugas**—melainkan menjadikan proses tersebut **tercatat, terverifikasi, dan dapat dipertanggungjawabkan secara digital**.
